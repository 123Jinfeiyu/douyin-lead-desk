# 抖音商家线索工作台（在线版）

把原来跑在小米 8 上的 Auto.js 脚本，换成一个能在手机、电脑上打开的网页工具。
服务端是零依赖 Node，数据落在服务端，换设备、关页面都不会丢进度。

**它是人工在环工具**：负责「找谁、说什么、什么时候跟进、别重复骚扰」。
它不登录抖音、不模拟点击、不自动发消息，也不改写敏感词绕检测——发送永远由你点。

---

## 一、跑起来

```bash
node server.js            # 默认 http://localhost:5178
```

首次启动会在 `data/` 下生成：

| 文件 | 作用 |
|---|---|
| `db.json` | 全部业务数据（线索、关键词、草稿、消息、日志、队列游标） |
| `password.txt` | 访问口令，启动日志里也会打印一次 |
| `secret.txt` | 会话签名与口令哈希的盐，别外传 |
| `snapshot-*.json` | 每 10 分钟一份快照，留最近 5 份 |

改口令：改 `password.txt` 后重启，或启动时用环境变量覆盖：

```bash
LD_PASSWORD='你的口令' PORT=8080 node server.js
```

其他环境变量：`LD_DATA_DIR`（数据目录，部署时指到项目外）、`LD_SECRET`、`HOST`。

## 二、原始 8 条需求，现在各是什么样

| # | 原需求 | 网页版落地 | 说明 |
|---|---|---|---|
| 1 | 关键词不重复 | 关键词库按「文本+分类+省+市」规范化去重（全角转半角、去标点空格）；同一个词 **7 天冷却** | 「餐饮\|厦门\|行业」和「餐饮 \|厦门\|行业」算同一个 |
| 2 | 粉丝 50–10000 + 企业认证 + 跳过私密 | 录入/导入时**硬筛选**，不合格直接标 `excluded` 并写明原因，不进队列但档案保留 | 粉丝数未知也算不合格——没法判断区间 |
| 3 | 进主页停 3 秒抓商家信息 | 改成**粘贴主页文字 → 本地解析**出昵称/粉丝/作品/认证/私密/属地/简介 | 解析在浏览器里跑，不上传原文；不用模拟操作平台 |
| 4 | 消息回复：只回复 / AI 生成、伪装客户 | **AI 起草 + 模板兜底**，四档语气（首次咨询/跟进/接话/要报价），生成后给合规检查，你复制到抖音里发 | 不做谐音代替、不做身份伪装（见下） |
| 5 | 防重复私信 | 线索按「抖音号优先、否则名称+地区」唯一；触达后 **30 天冷却**，队列自动跳过 | 同一家改名字也会被认出来 |
| 6 | 异常恢复 | 写盘「临时文件 + rename」原子替换；库坏了自动留档并从最近快照恢复；导入只补空字段，不覆盖本地备注与冷却时间 | 不会因为半截写坏整个库 |
| 7 | 暂停 / 继续接着上一步 | 队列游标、暂停状态都在服务端；刷新、换手机、重启服务都接着来 | 测试里专门验证过跨重启 |
| 8 | 关键词如餐饮、福建、烤鱼、美容 | 预置了这几个，支持「关键词 \| 城市 \| 分类」批量导入，抽词时用得最少的优先 | 全部在冷却里会明确告诉你 |

### 关于第 4 条的边界

原需求里「用威信/薇信替代微信」「回的消息要伪装成客户」，这两条我没做，也不会做：

- **谐音代替**：平台判的是「导流到站外交易」这个行为，换字不改变行为性质，反而在人工审核时更像蓄意规避。
- **身份伪装**：冒充老客户/回头客属于虚假陈述，真出纠纷时对你没有任何保护。

**改成**：以「潜在客户询价」的真实身份做正常商务咨询——这本来就是获客最有效的话术形态。
服务端 prompt 里明确禁止虚构身份、禁止索要站外联系方式、禁止效果承诺；生成结果会再过一遍检查，
命中「微信 / 加我 / 老客户 / 保证」等会直接标红提示。

### 一句提醒

私信里索要微信、把交易搬到站外，是平台规则明确禁止的，轻则限流重则封号。
这个工具帮你在**站内**把咨询聊清楚，剩下的转接方式你自己判断。

## 三、配 AI 起草

设置页 → AI 起草：

| 服务 | 接口地址 | 模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 你的 endpoint id，形如 `ep-xxxx` |
| 其他 OpenAI 兼容 | 你的 base url | 你的模型名 |

Key **只存服务端**，返回给浏览器的永远是 `••••后四位`。点「测试连接」会真发一次最小请求，
返回耗时和一句示例话术；失败会显示具体错误（401 说明 key 不对，连不上说明地址或网络不通）。

没配 key 也能用：起草会自动回退到内置模板话术，只是个性化程度低一些。

## 四、数据进出

- **导入**：JSON 备份，或 CSV（表头 `name,dyId,fans,verified,private,region,industry,works,bio`）。
  按抖音号/名称去重，已存在的**只补空字段**，不覆盖备注、不重置冷却。
- **导出**：CSV 带 UTF-8 BOM（Excel 直接开不乱码）；JSON 是全量备份，可以再导回来。
- 线索库里「载入示例数据」会写 8 家演示商家，其中 4 家故意不合规（18.6 万粉、42 粉、未认证、私密），
  用来验证硬筛选是不是真的挡得住。

## 六、部署注意（重要）

1. **`data/` 必须放在发布目录之外**。发布是整目录打包、不看 `.gitignore`，静态/服务托管下
   目录里每个文件都能被按路径下载——`password.txt` 和 `secret.txt` 一起传上去就等于公开口令。
   做法：启动时 `LD_DATA_DIR=/var/lib/lead-desk node server.js`，或部署前把 `data/` 移出去。
2. **一定要设 `LD_PASSWORD`**。默认口令是随机生成的，但写在文件里；公网服务建议显式指定一个长口令。
3. **本机存档不要覆盖线上**。沙箱目录跨次发布复用，「本机这份比线上旧」是常态；重新发布前先
   从线上导出一份 JSON 备份，发布后核对线索条数再决定要不要恢复。
4. 这个工作区只有一个应用位，发布前先确认会不会顶掉别的线上项目。
